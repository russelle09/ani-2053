# il est question ici de rediger les regles de conduite pour un groupe de quatre etudiants

lorsque plusieurs personnes travaillent ensemble sur un meme projet sur un meme depot Git, plusieurs regles doivent etre definir pour faciliter le travail et la collaboration. cependant , voyons donc comment s'effectue le nommage des branche. Le nom de ta branche doit reffleter le type du travail que tu effectue et s'ecrit en minuscule sans espace entre les mots ou les lettres (utiliser de preference les tirets pour separer les mots). 
voyons le cas du contenue d'un commit. le commit doit avoir une phrase a l'imperatif et Le message doit être court, clair et précis. Il doit indiquer ce qui a été fait dans le commit.Il faut éviter de mélanger des modifications qui n’ont aucun rapport entre elles.Il vaut mieux créer plusieurs commits, chacun correspondant à une modification logique ou à un même sujet.Cela rend l'historique Git plus clair et plus facile à comprendre, annuler ou corriger.
 La question qui se pose maintement est de savoir "QUI RELIT QUOI?" Une modification doit être relue par au moins une autre personne, en privilégiant les membres qui connaissent cette partie du projet.ce n’est pas nécessaire que tout le monde relise chaque modification. La relecture peut être répartie entre les membres du groupe. nous retenons donc que au moins une autre personne doit vérifier la modification avant son intégration dans la branche principale.
Cependant, il est interdit d'integrer un code non verifier, modifier l'historique partager travailler sans synchroniser le depot. 
Aussi, lorsqu'une personne casse la branche principale, il ne faut surtout pas continuer a ajouter des modifications sur cette branche, identifier le commit responsable de ce probleme, prevenir les autres de la situation et corriger le probleme le plus tot possible, tester la correction avant de remettre sur cette branche, et enfin fusionner la correction dans cette branche principale c'est pour cela que l'on verifie avant de mettre dans la branche principale
